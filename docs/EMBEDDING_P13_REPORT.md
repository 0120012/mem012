# P1.3 批准后的异步刷新验收

日期：2026-11-06。基线：`2627855`。结论：P1.3 两个验收切片均通过；已有调用链无需修改产品代码。P1 阶段尚未完成。

## 时序与验证边界

实际调用链：`approve` → 审批事务提交 → `spawn_embedding_refresh` → `embedding_for_approve` → `generate_embedding_for_memory` → `refresh_memory_embedding`。
审批提交成功后才后台生成，HTTP 响应不等待模型；HTTP 成功只表示审批成功。

Python 通过本机 HTTP 请求临时 Axum 服务。驱动使用当前源码中的实际批准 handler、响应包装、后台调度、生成入口、源快照、目标登记、审批事务、搜索投影、自动关系和正常块存储函数及 SQL。
鉴权有效会话、项目配置、tokenizer 加载及 `generate_chunks` 使用隔离替身；后台调度只增加任务计数包装，内部仍调用真实 `tokio::spawn`。生成替身以信号量暂停，不依赖运行时长推断是否异步。
本次验证了实际 HTTP 批准入口到数据库发布的衔接；未验证生产鉴权、真实 tokenizer、真实模型或发送配额，不代替 P1.6 完整链路验收。

claude 连接分别创建唯一的 `p13_trigger_*`、`p13_finish_*` schema，每个测试连接固定 search_path。夹具包含源记忆、审批、关键词、关系、搜索投影、图标记，以及生产块表和目标表 DDL。未使用正式表。
测试结束后停止后台任务及临时服务，核对 schema owner 与表集合后删除夹具，确认 namespace 不再存在；临时编译目录自动清理。

## ① 审批提交后的异步触发

6 个场景通过：

| 场景 | HTTP | 已确认结果 |
| --- | --- | --- |
| create 批准 | 200 | 生成仍暂停时响应已返回；独立连接看到 active、审批记录删除及搜索投影已提交 |
| update 批准 | 200 | 生成仍暂停时响应已返回；审批与投影已提交 |
| delete 批准 | 200 | 源记忆删除，不调用生成 |
| 非法 create 状态导致审批失败 | 500 | 审批记录保留，不调用生成 |
| 源记忆存在但无审批记录 | 404 | 不调用生成 |
| 无源记忆及审批记录 | 404 | 不调用生成 |

create/update 生成阻塞点还以独立连接确认当前源版本的目标已登记，尚无新块发布；放行后等待后台任务结束再清理。
首次临时驱动编译混用了 Serde 缓存，连简单测试 handler 也无法满足 Axum Handler 约束。用 IntoResponse 编译探针找出兼容依赖后重跑通过；未修改产品代码，不计作产品缺陷。

## ② 后台完整发布与失败收尾

create/update 各执行下列 3 种结果，共 6 个场景通过。所有场景审批 HTTP 均返回 200，后台结束后源记忆仍 active、审批记录仍已删除、搜索投影存在；审批响应 data 为 null，没有索引成功声明。

| 后台结果 | create | update |
| --- | --- | --- |
| 正常生成 | 发布完整三块及当前策略/代号 | 完整替换原两块，保存当前策略/代号 |
| 生成第二块时返回错误 | 不发布任何块 | 原索引全部字段及发布标记保持不变 |
| 第二块 INSERT 触发 CHECK 失败 | 删除及首块写入整体回滚，无残块 | 删除及首块写入整体回滚，原索引全部字段及发布标记保持不变 |

合成正文 `中a😀` 的 UTF-8 范围为 `[0,3)`、`[3,4)`、`[4,8)`，各块独立向量及标题路径；成功时逐块核对序号、范围、路径、维度、源版本、策略和生成代号。
生成失败替身在构造首块后、第二块处返回 Err，不交付半套结果。写入失败以夹具 CHECK 注入，后台继续使用实际刷新事务。
每个场景在暂停期间确认旧索引尚未变化，结束后比较完整数据库记录；失败时新生成目标保留，已发布旧块不被误标为当前策略。
捕获实际后台 stderr：两次生成失败均出现对应记忆的 `embedding refresh skipped`，两次写入失败均出现 `embedding refresh write failed`，成功场景无这两类错误。测试日志核对通过。
