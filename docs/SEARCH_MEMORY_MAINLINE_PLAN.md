# search_memory 聚合搜索升级主线计划

更新：2026-11-09。状态：规划完成，尚未实施。

本文件是本次 `search_memory` 升级的唯一执行计划，原 embedding 计划中的搜索开发和验收任务由本计划接管；embedding 迁移及配置表移除工作仍由 [embedding 主线计划](EMBEDDING_ITERATION_MAINLINE_PLAN.md) 维护。

## 目标与输入约定

升级后的 `search_memory` 只有一种搜索方式：AI 同时提供想查找的内容和确定的关键词，工具并行执行字面与向量召回，按整条记忆严格过滤，合并去重后统一判断相关性，最后返回有限数量的候选记忆。没有相关结果时允许返回空列表。

query 表达“想找什么”，用于字面路的相关性排序、向量查询和重排，不要求原文完整出现。include 表达“原文必须包含什么”，是两路共同遵守的硬条件；exclude 表达“原文不能包含什么”。AI 应选择少量有把握的关键词，不把整句 query 拆成大量必含词。只要缺少任一 include，即使语义相似也不能返回，这是聚合搜索明确保留的约束。

计划采用以下统一请求：

```json
{
  "query": "把网页保存成 Markdown 的方法",
  "terms": { "include": ["Markdown"], "exclude": ["付费"] },
  "filters": [],
  "limit": 5
}
```

query 必须是去除首尾空白后非空的字符串；terms 必须提供，include 必须包含至少一个有效字符串，关键词只去除首尾空白。其余参数采用以下默认约定：exclude 可省略，默认空数组；filters 可省略或为空数组，表示全部五个可搜索字段；limit 省略或为 null 时沿用后端默认值，其他值沿用既有正整数与后端上限规则。字段白名单仍为 title、summary、keywords、content、recall_when。未知参数、非法类型、空白关键词及非法字段在检索和模型调用前拒绝。

缺少 query、缺少 include、include 为空，以及只有 exclude 的请求都不再合法。升级不保留另一套兼容搜索分支，也不把 include 拼接成 query 的替代输入；调用方和工具说明须一起迁移。

当前仅完成这份升级计划，契约、样本和代码均未按新接口实施。工作顺序为：先更新契约与评测资料，再完成八项开发，统一审查和修复后集中测试，最后验证实际发布入口。开发期间只做静态核对和必要的编译检查，不逐项穿插行为测试。

## 完成标准

新接口通过真实 CLI/工具入口验证，合法请求能够完成聚合搜索，非法请求在检索和模型调用前拒绝。新版冻结契约与标注用例全部通过，严格过滤违规、跨 profile 泄漏、UUID 重复和返回超限均为零；正常空结果、单路降级、重排降级和执行失败可区分。调用说明与实际发布版本保持一致，全部开发、审查、验收和发布验证完成后，才能报告升级完成。

## 实施步骤

- [ ] [文档] **先固定新接口、响应约定和验收样本。**

   修订 [P0 搜索契约](EMBEDDING_P0_CONTRACT.md)，明确 query 与 include 的职责、默认值、必填规则和错误行为。返回正常或降级结果时沿用顶层 success，在现有 data.strategy 中标明是否降级及原因；两路召回均失败时返回顶层错误，正常空结果与降级空结果必须可区分。同步梳理 [CLI 搜索文档](cli/search_memory.md)、面向 AI 的工具参数定义和相关技能调用示例，统一使用聚合搜索说明。

   为 [搜索样本](embedding_search_samples.json) 增加 query 并重新核对标注，补充同义表达、query 与 include 分工、关键词满足但意图无关、非法空输入和组合约束场景。旧版“禁止 query”和“纯排除合法”的预期必须改写，不能机械补一个 query 后继续套用。保留 tune 调参、holdout 验收、contract 检查确定性规则的分工，在开发前冻结新版样本、标签、数量和质量标准。旧版 28 个检索用例、18 个非法请求及 27/28 结果只作历史参考；复用旧语料不宣称为新的独立留出验证。完成后，新契约和样本可以直接作为后续开发及验收依据。

- [ ] [项目代码] **接通统一输入，让请求能够到达搜索入口。**

   调整工具路由中直接拒绝 query 的逻辑，并在搜索入口统一校验新请求。query 去除首尾空白后作为模型查询文本，保留正常自然语言表达，不解析为布尔指令；include/exclude 保留顺序、大小写、重复项和词内空格，分别用于硬条件判断。完成后，合法聚合搜索请求能贯通真实路由，所有非法输入在数据库检索及模型调用之前被拒绝。

- [ ] [项目代码] **让两路候选满足相同的硬条件。**

   在选定字段的完整文本中，以不区分大小写的子串匹配检查全部 include 和 exclude。关键词可以分散在不同字段、章节和块中，字段外内容不参与判断；向量命中某个块后，也按整条记忆的当前工作态检查。两路都只读取当前 profile，允许 active 和 pending，排除 trashed。硬条件应在每路候选上限生效前完成，避免不合格结果占据名额。pending 记忆仍可经字面路召回，证据读取当前文本，不将旧向量对应的旧文本当作当前内容。完成后，召回来源不会改变记忆是否符合用户条件。

- [ ] [项目代码] **并行召回，并为后续重排保留足够候选。**

   每个合法请求同时启动字面与向量召回，字面已有结果也继续执行向量路。字面路在硬条件范围内按 query 的字面相关性排序选择候选，向量路使用 query 生成查询向量；query 的完整短语或拆出的词不作为 include 之外的字面硬条件。候选数量与最终 limit 分开，limit=1 也能保留多条候选。候选预算和相关性阈值仅在统一验收的 tune 阶段确定并冻结，不能直接把既有返回上限当成候选预算，也不用 holdout 调参。保留现有模型、维度、距离阈值及索引切换保护。完成后，两路实际重叠执行，用户的 limit 和 query 表述不会被误当作额外的硬过滤。

- [ ] [项目代码] **按记忆合并多块和双路命中。**

   向量块先在当前 profile 内按 UUID 归并为记忆，再占用候选名额；两路合并后，同一 UUID 只保留一条，内容相同但 UUID 不同的记忆分别保留。记录召回来源、字面路命中的身份及命中字段或块的位置，保持合并次序可复现。两路原始分数只用于各自路径的候选选择，不相加，也不跨路比较。完成后，每条记忆只进入一次重排，并保留证据收集所需的位置及故障降级所需的字面候选集合。

- [ ] [项目代码] **收集既能证明关键词命中、又能判断 query 相关性的原文证据。**

   在选定字段中定位每个 include 的真实位置，收集跨字段、跨章节的自然原文，保留字段名和章节路径，合并重叠范围。同时结合字面命中与向量命中位置，保留判断 query 所需的相关段落及上下文，不依赖整句 query 出现。例如 include 只在标题出现时，也要保留正文中真正说明如何保存网页的段落。字段外内容不作为相关性依据。完成后，重排既能看到每个必含词的依据，也有足够上下文判断该记忆是否符合 query。

- [ ] [项目代码] **在模型预算内组装每条记忆的重排文档。**

   每条记忆对应一份文档，按实际 tokenizer 检查模型预算，并计入 query 和必要上下文。超出预算时先缩短外围上下文，保留每个 include 的依据及判断 query 相关性所需的原文；仍然放不下时进入明确降级，不提交缺失关键依据的文档。完成后，提交给模型的每份证据都在预算内，并能支持完整判断。

- [ ] [项目代码] **用 query 统一判断相关性，并校验完整评分。**

   有候选就执行相关性判断，即使只有一条也不跳过。每条记忆只对应一个评分，先过滤低相关结果，再排序；全部不相关时返回正常空结果。不能因为满足 include 或命中准确名称就绕过成功的重排判断。空响应、部分评分、重复或越界索引、非有限分数均按重排失败处理。完成后，最终排序围绕 query 展开，关键词仅负责约束可返回的范围。

- [ ] [项目代码] **接通故障降级和最终返回。**

   配置缺失、数据库或模型请求失败，与正常零命中分别处理。向量路失败时，对成功召回的字面候选继续完整重排；字面路失败时，向量候选满足全部硬条件并通过完整重排后才能返回。两路都失败则返回故障。证据无法完整保留或重排失败时，只保留已由字面路召回且满足硬条件的候选，并明确标记降级及原因；没有这类候选时返回降级空结果。

   证据或重排失败后的字面回退只保证硬条件成立，不能声称已经确认与 query 相关。结果保留既有记忆 ID、标题、摘要等字段，不把字面分数或余弦相似度冒充重排分数。最终 limit 在去重、相关性过滤和排序后应用，降级路径同样不超限。完成后，调用方能区分正常相关结果、未经完整相关性确认的回退候选及执行失败。

- [ ] [代码审查] **统一审查完整链路并修复问题。**

   八项开发完成后，审查从真实工具路由到最终响应的完整链路，重点检查 query 是否被误当硬条件、include 是否被放宽、证据是否完整、评分映射与降级是否正确，以及调用文档是否与接口一致。问题按小步修改后复核。此时只能标记“开发及审查完成，待统一测试”，不能宣称已验收。

- [ ] [测试验收] **统一验证聚合搜索行为与质量。**

   使用新版冻结样本，验证缺少或空白 query、缺少或空 include、只有 exclude、未知字段及其他非法输入均提前拒绝。验证 query 使用同义表述且未完整出现在原文中时仍能召回相关记忆，缺少任一 include 时仍不能返回，exclude 和 filters 的限制对两路一致。满足关键词但与 query 无关的记忆应被正常重排排除；例如“Markdown 入门教程”不能仅因命中 Markdown 就成为“保存网页的方法”的正常结果。

   其余覆盖实际并行、跨字段及章节命中、profile 与状态隔离、多块及双路去重、同文不同 UUID、limit=1 不提前截断、单路和双路失败，以及正常与降级空结果。证据与重排场景覆盖相关段落远离关键词位置、预算不足、单候选及全部候选低相关、评分响应缺失或畸形、重排失败只保留字面候选，以及没有字面候选时返回降级空结果。

   先在 tune 选定候选预算和阈值，再冻结参数执行 holdout；contract 不参与调参。新版契约与标注用例必须全部通过，泄漏、重复、超限和严格过滤违规均为零。分别记录版本、参数、结果、耗时及模型调用量，usage 缺失记 unknown，不以空结果掩盖故障，不放宽质量线来迎合结果。完整测试必须经过实际 CLI/工具入口，不能只调用内部搜索函数。

- [ ] [发布验证] **同步调用方，并确认实际运行的是新接口。**

   新请求不兼容缺少 query 或只提供 exclude 的旧调用，因此发布时同步工具参数说明、CLI 示例和记忆技能中的调用形状，确认 AI 使用统一聚合搜索。使用目标版本完成只读冒烟：合法请求、非法输入、可解释的空结果以及降级状态均符合新契约，再记录实际版本和验证结果。

   最近一次记忆 CLI 调用仍因查询不存在的 `public.memory_embedding_config` 失败，恢复情况尚未复核；发布须与移除配置表主线的已验收版本衔接，不能把源码已修改或本地编译通过当作实际运行环境已升级。该问题保持为独立发布依赖，避免混入搜索算法改动。
