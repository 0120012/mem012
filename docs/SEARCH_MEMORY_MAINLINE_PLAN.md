## 目标与输入约定

升级后的 `search_memory` 只有一种搜索方式：AI 同时提供想查找的内容和确定的关键词，工具并行执行关键词与向量召回，合并去重后统一进入 rerank，最后返回不超过 limit 的候选记忆。向量召回结果不要求包含关键词；没有相关结果时允许返回空列表。

query 表达“想找什么”，用于关键词路排序、向量查询和 rerank，不要求原文完整出现。include/exclude 约束关键词召回路；向量路独立按 query 召回，不因候选缺少 include 而提前丢弃。AI 应选择少量有把握的关键词，不把整句 query 拆成大量必含词。两路候选统一交给 rerank 判断相关性。

计划采用以下统一请求：

```json
{
  "query": "把网页保存成 Markdown 的方法",
  "terms": { "include": ["Markdown"], "exclude": ["付费"] },
  "filters": [],
  "limit": 5
}
```

query 必须是去除首尾空白后非空的字符串；terms 必须提供，include 必须包含至少一个有效字符串，关键词只去除首尾空白。其余参数采用以下默认约定：exclude 可省略，默认空数组；filters 可省略或为空数组，表示全部五个可搜索字段；limit 省略或为 null 时沿用后端默认值，其他值沿用既有正整数与后端上限规则。字段白名单仍为 title、summary、keywords、content、recall_when。未知参数、非法类型、空白关键词及非法字段在检索和模型调用前拒绝。

缺少 query、缺少 include、include 为空，以及只有 exclude 的请求都不再合法。升级不保留另一套兼容搜索分支，也不把 include 拼接成 query 的替代输入；调用方和工具说明须一起迁移。

两路候选合并后统一 rerank，以及 rerank 失败时的响应语义均已实施。工作顺序为：更新契约与评测资料，完成八项开发，统一审查和修复后集中测试，最后验证实际发布入口。开发期间只做静态核对和必要的编译检查，不逐项穿插行为测试。

## 已确认的接口决策

- 两路独立召回：关键词路按 terms 工作，向量路按 query 工作；向量候选即使不含 include 关键词，也允许进入合并集合和 rerank。
- 两路候选先按 `memory_uuid` 去重，再统一进入一次 rerank；rerank 成功后按重排结果排序并应用 limit。
- 合并去重后不足两条候选时跳过 rerank；零候选返回空列表，单候选直接返回。
- rerank 失败仍返回候选，保持顶层 `state="success"`；`data.results` 是两路去重后的回退结果，数量不超过 limit，`error` 直接为字符串 `"rerank_failed"`。
- rerank 失败的回退顺序采用关键词路优先的交替合并：关键词第 1 条、向量第 1 条、关键词第 2 条、向量第 2 条；重复 UUID 跳过，一路耗尽后取另一路。不比较两路原始分数，也不输出字面/向量分数冒充 rerank 分数。
- 单一路召回失败时继续使用另一条路，并以 `keyword_recall_failed` 或 `vector_recall_failed` 标记；两路都失败时返回 `state="error"`。单个故障使用错误字符串，多个故障使用数组，顺序固定为关键词、向量、rerank。
- 正常完成时 `error` 为 `null`；不再输出 `data.strategy`、`embedding_fallback` 或 `rerank` 字段。`data.count` 等于结果数且不超过 limit。

```json
{
  "state": "success",
  "tool": "search_memory",
  "data": { "results": [{ "memory_uuid": "{memory_uuid}" }], "count": 1 },
  "error": "rerank_failed",
  "profile": "{profile}"
}
```

   关键词路在选定字段的完整文本中，以不区分大小写的子串匹配检查 include 和 exclude；关键词可分散在字段、章节和块中，字段外内容不参与关键词判断。向量路独立使用 query 召回，不因缺少 include 而拒绝候选；合并前仍只读取当前 profile，允许 active 和 pending，排除 trashed，并按当前工作态读取证据。硬条件只约束关键词路，候选上限前完成关键词过滤，避免不合格关键词结果占据名额。

- [x] [项目代码·实现完成] **并行召回，并为后续重排保留足够候选。**

   每个合法请求同时启动字面与向量召回，字面已有结果也继续执行向量路。字面路在硬条件范围内按 query 的字面相关性排序选择候选，向量路使用 query 生成查询向量；query 的完整短语或拆出的词不作为 include 之外的字面硬条件。候选数量与最终 limit 分开，limit=1 也能保留多条候选。候选预算和相关性阈值仅在统一验收的 tune 阶段确定并冻结，不能直接把既有返回上限当成候选预算，也不用 holdout 调参。保留现有模型、维度、距离阈值及索引切换保护。完成后，两路实际重叠执行，用户的 limit 和 query 表述不会被误当作额外的硬过滤。

- [x] [项目代码·实现完成] **按记忆合并多块和双路命中。**

   向量块先在当前 profile 内按 UUID 归并为记忆，再占用向量候选名额；两路合并后，同一 UUID 只保留一条，内容相同但 UUID 不同的记忆分别保留。记录召回来源、关键词路命中的身份及命中字段或块的位置，保持合并次序可复现。两路原始分数只用于各自路径的候选选择，不相加，也不跨路比较。完成后，每条记忆只进入一次 rerank；若 rerank 失败，按已确认的交替规则回退并限制 limit。

- [x] [项目代码·实现完成] **收集既能证明关键词命中、又能判断 query 相关性的原文证据。**

   在选定字段中收集关键词路的命中位置，并结合两路命中位置保留判断 query 所需的相关段落及上下文，不依赖整句 query 出现。向量独有候选不要求存在 include 证据，但必须提供足够原文供 rerank 判断；字段外内容不作为相关性依据。完成后，rerank 文档既能看到关键词命中依据，也能判断向量独有候选是否符合 query。

- [x] [项目代码·实现完成] **在模型预算内组装每条记忆的重排文档。**

   每条记忆对应一份文档，按实际 tokenizer 检查模型预算，并计入 query、关键词命中证据（如有）和必要上下文。超出预算时先缩短外围上下文；仍然放不下时进入 rerank 失败回退，不提交缺失关键上下文的文档。完成后，提交给模型的每份证据都在预算内，并能支持完整判断。

- [x] [项目代码·实现完成] **用 query 统一判断相关性，并校验完整评分。**

   只有合并去重后至少两条候选时才调用 rerank；零条返回空结果，单条直接返回，不生成重排评分。至少两条时每条记忆只对应一个评分，先过滤低相关结果，再排序；全部不相关时返回正常空结果。不能因为满足 include 或命中准确名称就绕过成功的重排判断。空响应、部分评分、重复或越界索引、非有限分数均按重排失败处理。完成后，最终排序围绕 query 展开，关键词仅负责关键词路的硬条件。

- [x] [项目代码·实现完成] **接通故障降级和最终返回。**

   配置缺失、数据库或模型请求失败，与正常零命中分别处理。一路召回失败时，另一条路继续完成搜索和 rerank，并在 `error` 标明失败路；两路均失败时返回 `state="error"`，`error` 为包含两路错误码的数组。rerank 请求失败、响应缺失或结果畸形时，保持顶层 success，`error="rerank_failed"`，使用两路已合并去重的候选按交替规则回退，并限制在 limit 内。单个故障用错误码字符串，多个故障用按关键词、向量、rerank 顺序排列的错误码数组。

   rerank 失败后的回退结果只表示已被关键词路或向量路召回，不能声称已经确认与 query 相关。结果保留既有记忆 ID、标题、摘要等字段，不输出 `strategy`，也不把字面分数或余弦相似度冒充 rerank 分数。最终 limit 在去重后应用，回退路径同样不超限。完成后，调用方通过 `error=null`、单个错误码字符串或多个错误码数组区分正常结果、部分成功及多路故障。
