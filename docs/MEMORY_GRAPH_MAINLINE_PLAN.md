# 记忆关系与图谱优化主线计划

Git 基线为 `main` 的 `37710e9c5cf0799b94651d3c0f19c05560fc5adc`。

## 目标与约束

- 新版记忆明确指定被替代的旧记忆时，审批通过即自动保存 `新版 → supersedes → 旧版`，旧记忆原文可回查。
- SQL 按共同关键词筛选并排序候选。审批页展示候选，默认类型为 `related_to`，随记忆审批一起保存。用户可在图谱里手动改为 `depends_on`。首版用固定的默认类型。
- 前端以选中的记忆为中心展示直接关系，点击邻居可切换中心。`search_memory` 输出中的关系展示延期。
- PostgreSQL 关系表承载当前工作态，AGE 是可重建的投影。沿用现有 API 和审批语义。
- 开发按切片推进。全部开发项完成后，统一运行测试并验收。
- 升级时保留已有关系。旧边清理单独处理，先预览待删列表和恢复方案，经用户确认后按关系 ID 执行。

- [x] 复用现有关系 API 和审核撤销流程，支持在图谱里把已有关系手动改为 `depends_on`，并支持手动添加其他关系。

- [x] 调整总览选点，在节点数量上限内优先展示实际连通的记忆。

## 第二阶段 集中测试与验收

- [x] 用 PostgreSQL 验证一次审批即可保存新版、`supersedes` 和预览中的默认 `related_to`，旧版正文仍可读取。
- [x] 跑后端回归测试，验证用户可将 `related_to` 改为 `depends_on`，关系两端与方向保持一致，撤销可恢复原类型。
- [x] 验证候选查询只读，按共同关键词排序。仅同分类且无共同关键词的记忆不入选。
- [x] 验证升级后原有边仍可读取，用历史样本核对盘点项。验证人工改成 `depends_on` 的边即使保留旧备注，也归入保留项。
- [x] 验证图谱查询。归档邻居后连边和空节点消失，总览优先展示连通记忆，且每条返回边的两端均可见。
- [x] 在前端验证局部图的平行边和方向可辨，点击邻居能切换中心。验证浏览为只读操作，显式 AGE 重建入口可用。

验收使用与 VPS 部署相同镜像的隔离 PostgreSQL 18.6、真实 mem012 API 和 Chrome。历史样本由基线 SQL 生成。过期审批预览返回冲突且事务回滚，显式重建后使用 Cypher 查询确认 AGE 中的方向和边类型。`cargo test --locked --offline` 通过 125 项，2 项按测试定义忽略。
