# P1.2 正常块存储验收

日期：2026-11-06。结论：P1.2 存储契约及隔离验收通过；P1 阶段尚未完成。

## 实现与边界

正常块表以 `(memory_uuid, chunk_index)` 定位块，保存源版本、模型、维度、正文范围、标题路径及发布策略/生成代号。
生成前登记每条记忆的目标，递增代号区分同维度策略变化及 A→B→A；生成失败保留目标和已有块。
发布事务锁定 active 源行，核验源快照/revision、当前目标及载荷模型/维度，完整性校验通过后删除旧块、插入整套新块。
源与目标锁持续至事务结束；任一 SQL 失败由刷新事务回滚，内容及发布标记一起恢复。

## 隔离验收方式

- 以 `rustc --edition=2021` 和当前缓存依赖编译临时驱动，提取当前仓库的实际 `refresh_memory_embedding`、`register_embedding_target`、`validate_embedding_source`、`upsert_approved_embedding`、`memory_state` 及 `MEMORY_STATE_SQL`。仅调整模块路径，不替换业务逻辑。
- claude 连接创建唯一命名 `p12_verify_*` schema；夹具含源表、关键词、关系、生产块表 DDL 和生成目标表 DDL。每个测试连接通过 URL `options[search_path]` 指向该 schema。
- 向量是合成的有效二维数据；来源由实际源快照 SQL 读取，版本变化由测试显式更新。未调用模型、HTTP 审批入口或正式迁移，也未使用正式表。
- 实际刷新负责事务提交/回滚。并发可见性及目标锁测试额外直接调用实际写入函数，使用标准输入控制事务提交/回滚；通过 `pg_stat_activity` 确认竞争连接处于 Lock 等待。
- 失败前后比较已发布记录全部字段；成功时逐块核对范围、路径、源版本、策略及代号。测试结束核对 schema owner 后删除夹具，确认 namespace 不再存在，临时编译目录自动清理。

## 通过的 11 组场景

| 场景 | 已确认结果 |
| --- | --- |
| 实际刷新连续替换 1/3/2/1 块 | 仅保留完整新集合，各块目标标记与任务一致 |
| 同维度新策略先发布、旧任务晚完成 | 旧任务拒绝，已发布新索引不变 |
| 登记新目标但不发布结果 | 原索引不变，旧目标任务仍被拒绝 |
| A→B→A | 最初 A 任务不能重新匹配新 A 目标 |
| 源正文及 revision 变化 | 实际完整快照比较拒绝旧来源，原索引保留 |
| pending/trashed 来源 | 实际刷新跳过，原索引不变 |
| 载荷模型或维度与目标不同 | 拒绝发布，原索引不变 |
| 第二块触发 CHECK 失败 | DELETE 和第一块 INSERT 全部回滚，旧标记也恢复 |
| 发布事务未提交时并发登记 | 读者仍见旧集合，登记等待源锁；新目标登记后旧任务拒绝 |
| 发布期间直接更新目标 | `FOR SHARE` 阻止目标变化；发布事务回滚后原集合不变 |
| 源编辑先持锁再刷新 | 刷新确认等待锁，源提交后拒绝旧 revision |

首次执行在通过第一组后发生子进程超时及数据库连接关闭，未计作通过。重连后核对残留测试 schema 内容及 owner，清理且确认无测试会话；放宽临时进程等待上限后重跑，以上 11 组全部通过并清理成功。
