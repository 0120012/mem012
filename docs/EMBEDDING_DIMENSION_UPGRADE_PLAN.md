# 可重复、限速的向量索引迁移计划

## 目标与约束

- 用户确认现有数据库向量为 768 维；已在测试 profile `claude` 的 `mem_claude` 核验旧表为 `vector(768)`、共 5 条向量。
- 按用户要求先在 `claude` 测试建表；`codex` 尚未执行升级准备命令。
- 首轮目标模型为 `BAAI/bge-m3`、1024 维；后续迁移由命令指定目标模型及其支持的维度，不写死 1024。
- 用户确认首版仅支持 1～2000 维，继续使用 HNSW；超范围目标在建表及模型请求前拒绝，不引入精确检索或高维近似索引分支。
- 按 `DB_PLAN.md` 的维度升级流程准备 `memory_embeddings_next`，完成回填与索引后切换。
- 切换前保留旧表及匹配的查询模型、维度；不清空旧向量，不 reset 数据库。
- 新表使用块记录结构，保留 `source_revision`，不引入 `source_hash`、`index_version`。
- 现有读写 SQL 固定使用 `memory_embeddings`；已接入的 `prepare-embedding-upgrade` 仅能准备 1024 维空表，尚无完整迁移能力。
- 每轮仅交付一个最小切片，只改一个小函数且逻辑 diff 小于 35 行。

## 固定流程设计（待实现）

- 对外提供一个迁移命令，负责准备、限速回填、校验、索引准备、切换、查询验证和收尾；相同目标再次执行时恢复已有进度。
- 命令示意：`mem012 --profile claude migrate-embeddings --model BAAI/bge-m3 --dimension 1024 --rpm 30 --tpm 30000`。这是待实现接口；30 RPM / 30000 TPM 是保守示例，不是服务商限额或已落地配置。
- 每个 profile 保存当前索引和目标索引的模型、维度、物理表、处理策略及任务阶段；任务保存进度、配额消耗和最近错误。凭据引用现有配置，不写入任务记录。
- 一个 profile 同时只运行一个迁移目标。目标冻结后才能续跑；旧任务晚完成时校验目标及源 revision，不能覆盖新目标。
- 固定复用两个索引槽位：一个服务当前查询，一个准备目标或保留上一代。完成验收后才允许下次迁移回收非活动槽位，不无限累积历史表。
- 同一次查询的向量模型、维度、检索阈值和物理表必须来自同一代；切换更新数据库中的当前代记录，避免配置文件与表路由分别切换。
- 保留块的 `source_revision`，不重新引入每块 `source_hash` 或 `index_version`；迁移配置及进度集中保存。

流程：

```text
检查目标能力 -> 准备目标槽位 -> 限速生成并回填 -> 补扫并校验
                                     ^              |
                                     +-- 源过期 ----+
       -> 准备检索索引 -> 原子切换当前代 -> 查询验证 -> 完成
                                                        |
                            下一次目标迁移 <-------------+
```

- 网络请求期间不锁源记忆；写入时以一条记忆的完整块集合为单位，事务核对源 revision 和任务目标。失败不发布半套索引。
- 游标只辅助进度；恢复及切换前重扫缺失、源过期或不完整的目标记录，不能漏掉游标之前发生的修改。
- 切换前在一致的锁边界内再次核验完整性；检查失败则继续回填，旧代继续服务。切换后验证失败时保留可恢复的旧代路由。
- 暂停、请求失败或进程退出保留已完成进度；同一目标重跑跳过有效记录。不另建重试队列。

限速与资源：

- 用户确认且 P0 已记录的上限为 2000 RPM、500000 TPM，保守视为共享额度；不把服务上限当作迁移目标速度。
- 默认采用单请求并发、小批读取及逐记忆处理，避免一次加载全部正文或向量；目标模型的 tokenizer、上下文和元信息均计入输入预算。
- 迁移速率、共享账户 RPM/TPM 及单次任务预算共同约束请求，重试也计数；遇到 429 按服务端等待提示和退避规则放慢，预算耗尽时暂停并可续跑。
- 所有迁移及在线 embedding 入口需要共用账户级调度；独立 CLI 进程分别计数不能保证共享额度，执行归属需在接入时统一。
- 新旧索引并存期间需要两代磁盘空间；限速主要降低瞬时 API、CPU 和内存负载，完成验收后复用非活动槽位限制存储增长。

能力核验：

- `claude` 的 pgvector 0.8.7 临时表实测：`vector(1024)` 可建 HNSW，2048/4096 维向量列可创建，但 `vector` HNSW 报错：最高 2000 维。验证已全部回滚。
- 用户已确认暂不支持 2000 维以上；建表 API 已限制目标范围为 `1..=2000`，完整迁移入口后续沿用相同边界。
- 模型必须实际支持目标输出维度；改数据库维度不能把现有向量自动变成新维度。
