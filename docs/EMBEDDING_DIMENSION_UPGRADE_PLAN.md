# 可重复、限速的向量维度迁移计划

**计划归属：** 本文是[记忆 embedding 迭代主线计划](EMBEDDING_ITERATION_MAINLINE_PLAN.md)的拆分执行计划。块索引、生成、限速、回填和一致性保护对应主线 P1；换表及恢复能力先在隔离环境开发验证，目标环境操作仍归属 P5，须等待 P4 达标并另行确认环境范围。专项完成不等于 P1 或主线完成。

**同步规则：** 本文记录专项切片与详细验证证据；完成切片或确认设计变更后，同时更新主线的阶段状态、相关约束与剩余范围。日常批准后的刷新、同维度内容/策略更新及正常读写链路不因本专项简化而取消。

## 目标与约束

- 用户确认现有数据库向量为 768 维；已在测试 profile `claude` 的 `mem_claude` 核验旧表为 `vector(768)`、共 5 条向量。
- 按用户要求先在 `claude` 测试建表；`codex` 尚未执行升级准备命令。
- 首轮目标模型为 `BAAI/bge-m3`、1024 维；目标模型由用户在 `config.toml` 的 `[embeddings].embeddings_model` 配置，命令只指定目标维度，不增加 `--model`。
- 当前优先跑通 `claude` 的 768 → 1024 完整流程；维度迁移不限制升降方向，均由目标模型重新生成，不按旧向量补零或截断。
- 用户确认首版仅支持 1～2000 维，继续使用 HNSW；超范围目标在建表及模型请求前拒绝，不引入精确检索或高维近似索引分支。
- 按 `DB_PLAN.md` 的维度升级流程准备 `memory_embeddings_next`，完成回填与索引后切换。
- 切换前保留旧表及匹配的查询模型、维度；不清空旧向量，不 reset 数据库。
- 换表仅用于目标维度与当前维度不同的迁移；同维度不走换表流程。每轮清理非活动槽位并按新维度重建、全量生成，不判断旧块复用，不做断点续跑；仅清空行不会改变 `vector(n)` 的维度。
- 新表使用块记录结构，保留 `source_revision`，不引入 `source_hash`、`index_version`。
- 现有读写 SQL 固定使用 `memory_embeddings`；`prepare-embedding-next` 已接入准备、限流及最小回填循环，三项参数均必填。尚无建索引、全库覆盖补扫或切换能力。
- 每轮仅交付一个最小切片，只改一个小函数且逻辑 diff 小于 35 行。

## 固定流程设计（待实现）

- 复用现有命令，统一改名为 `prepare-embedding-next`，逐步扩展为准备、限速回填、校验、索引准备、切换、查询验证和收尾的完整流程；重新执行从清理非活动槽位开始，不另增并列命令。
- 命令示意：`mem012 --profile claude prepare-embedding-next --dimension 1024 --rpm 50 --tpm 500000`。目标模型沿用 `config.toml`；三项参数均必填，无默认值，50/500000 仅为填写示例。已接入进程内请求限流及最小回填循环；当前 tokenizer 仅支持 BGE-M3，其他模型在重建前拒绝。
- 本阶段不新增 profile 当前代、目标代和迁移阶段记录表；沿用现有表和 `memory_embeddings_next`，结合配置中的模型与命令指定的维度确定目标。准备前核对当前维度，同维度不换表。
- 一个 profile 同时只运行一个迁移目标，执行期间互斥；确认目标槽位非活动后才清理并重建，禁止清空当前服务表。写入仍核验源 revision。
- 固定复用两个索引槽位：一个服务当前查询，一个准备目标或保留上一代。完成验收后才允许下次迁移回收非活动槽位，不无限累积历史表。
- 同一次查询的向量模型、维度、检索阈值和物理表必须匹配；切换时协调现有配置与表路由，具体实现留到切换切片，不依赖新增当前代记录。
- 保留块的 `source_revision`，不重新引入每块 `source_hash` 或 `index_version`；用于本轮回填及切换前检查源内容是否变化，不用于跨任务复用旧块。

流程：

```text
确认维度变化及目标能力 -> 清理并重建非活动槽位 -> 限速生成并回填 -> 补扫并校验
                                     ^              |
                                     +-- 源过期 ----+
       -> 准备检索索引 -> 原子切换当前代 -> 查询验证 -> 完成
                                                        |
                            下一次目标迁移 <-------------+
```

- 网络请求期间不锁源记忆；写入时以一条记忆的完整块集合为单位，事务核对源 revision 和任务目标。失败不发布半套索引。
- 在命令进程内串行循环处理本轮 active 记忆，逐条打印记忆标识及成功或失败 JSON；整轮互斥，单条失败继续，最终退出码非零。内部窗口计数仅服务 RPM/TPM 限流，不另做耗时估算或累计用量统计模块。当前已实现；不自动脱离终端成为守护进程。
- 游标只辅助本轮进度；切换前重扫本轮缺失、源过期或不完整的目标记录，不能漏掉游标之前发生的修改。
- 切换前在一致的锁边界内再次核验完整性；检查失败则继续回填，旧代继续服务。切换后验证失败时保留可恢复的旧代路由。
- 请求失败且重试耗尽或进程退出时不切换；下次执行重新清理并生成，不恢复上轮进度，不另建重试队列。

限速与资源：

- 用户确认且 P0 已记录的上限为 2000 RPM、500000 TPM，保守视为共享额度；迁移 RPM/TPM 均由用户显式填写，无默认值。必须执行实际限速，内部按时间窗口计数；迁移参数本身尚不代表共享账户额度已协调。
- 默认采用单请求并发、小批读取及逐记忆处理，避免一次加载全部正文或向量；目标模型的 tokenizer、上下文和元信息均计入输入预算。
- 迁移速率及共享账户 RPM/TPM 共同约束请求，重试也计数；遇到 429 按服务端等待提示和退避规则放慢。不新增独立的任务用量预算模块。
- 迁移复用现有 embedding 请求及重试链路；共享账户额度如何协调留到限速切片处理，不作为代记录表的前置工作。独立 CLI 进程分别计数不能保证账户级额度。
- 新旧索引并存期间需要两代磁盘空间；限速主要降低瞬时 API、CPU 和内存负载，完成验收后复用非活动槽位限制存储增长。

能力核验：

- `claude` 的 pgvector 0.8.7 临时表实测：`vector(1024)` 可建 HNSW，2048/4096 维向量列可创建，但 `vector` HNSW 报错：最高 2000 维。验证已全部回滚。
- 用户已确认暂不支持 2000 维以上；建表 API 已限制目标范围为 `1..=2000`，完整迁移入口后续沿用相同边界。
- 模型必须实际支持目标输出维度；改数据库维度不能把现有向量自动变成新维度。
