## 已确认的迭代方向

- 首要目标：找回长记忆中的具体细节，同时减少无关结果。
- 对外结果：继续返回记忆标题、摘要和 ID，由调用方 read_memory 回读全文；不要求新增命中片段展示。
- 准确性优先：相关性不足时允许少返回或返回空结果，不为凑数量保留弱相关候选。
- 内容范围：多项目 GitHub Trending 合集、完整 skill/prompt 文档，以及简短的问题和关键节点记录。
- 查询方式：既有准确名称/关键词查找，也有按用途和特征描述查找。
- 用户提出将字面召回与向量召回并行执行，合并结果并去重；include 使用 AND 是正确的既有语义，应保留。
- 已确认流程：字面与块向量并行召回 → 按 memory_uuid 去重并汇集命中依据 → 每条记忆一份证据文本统一 rerank → 相关性过滤 → 最终 limit。两路原始分数不直接比较或相加。
- 已确认契约：只保留 include / exclude / filters 高级搜索；include 拼接文本用于 embedding/rerank，其 AND 与 exclude 同时约束两路，并作用于整条记忆的选定字段。
- Code Trace：即使两路均保留 AND，由于分别按字面相关性与向量距离取有限候选，合并仍可能补入另一种排序下的候选；但不会扩展到缺少 include 原词的记忆。该结论尚未经真实数据库验证。
- 上述为计划方向，尚未修改程序或恢复记忆。

### 搜索输入与过滤契约

- 目标 API/工具只支持高级搜索 terms.include、terms.exclude 和 filters；删除普通搜索 query 参数及 query-only 检索路径，不保留兼容入口，也不新增独立检索描述参数。当前源码中的旧 query-only 分支是待移除项。
- 高级搜索从 terms.include 派生内部 include_text（规范化后以空格拼接）；它是唯一检索意图，不是新的用户参数。
- terms.include 继续作为严格 AND，terms.exclude 继续作为严格排除；两路都遵守同一组状态、profile、filters 与 terms 边界。
- include_text 同时作为向量查询和 rerank query；字面路也用 include 词做相关性评分、命中位置定位与正文证据提取。关键词既承担包含约束，也表达检索意图，不擅自放宽为软条件。
- terms 仍作用于整条记忆的选定字段，不要求全部词出现在同一个块里；filters 只限定这些硬条件的匹配字段。
- 保持既有高级参数规则：terms 与 filters 同时提供，include 与 exclude 两个数组都提供，至少一组非空。仅有 exclude 时保持纯过滤，不调用 embedding/rerank。
- 示例：include = ["网页", "Markdown"]；exclude = ["付费"]。两路结果都必须包含“网页”和“Markdown”、不含“付费”，并用“网页 Markdown”进行语义排序。
- 并行向量路用于改善符合严格条件的候选排序与长文细节召回；不会召回缺少 include 必选词的记忆。这是已确认的约束，不作为放宽 AND 或恢复普通搜索的理由。

### 内部按块，外部按记忆

- 保留 memory_units 及 read_memory 全文接口；新增的分块文本和向量仅是可重建的派生索引。
- 短记忆一个块；长文优先按 Markdown 标题、项目条目、段落与代码围栏划分，过长章节再按匹配模型的 token 预算拆分，必要时少量重叠。
- 章节再次拆分后的每个续块都携带精简的标题路径；上下文前缀计入预算，避免只给首块标题或让重复上下文挤占正文预算。
- GitHub Trending 的各项目优先形成独立内容块；完整 skill/prompt 保留章节路径，避免把无关项目与章节混在一个向量里。
- 每块保存 parent memory_uuid、块序号、正文范围、标题路径与 embedding；向量输入携带记忆标题和章节上下文。关键词/recall_when 等元数据的具体使用需通过样本检验，避免无关标签污染所有正文块。
- 不再将多块平均合成一条向量；完整正文保持原样。运行成本通过排队和预算控制，超限明确失败/待处理，不静默丢弃尾部。
- 分块预算适配 embedding 的实际 token 限制；rerank 证据文本按模型输入窗口整理，考虑 include_text、标题/章节路径、证据正文和特殊 token。不把字符数当作 token 数，也不为 include_text 另设应用层长度上限或专门超限规则；初始块大小、证据预算与重叠量由样本选择。

### 并行召回、去重与相关性判定

1. 同一请求下并行执行 pg_trgm 字面路与按块向量路；复用 PostgreSQL/pgvector，不新增搜索服务或模型种类。
2. 字面路在选定字段上对整条记忆严格执行 include AND / exclude，并基于 include 词的命中字段、次数、位置及 pg_trgm 相似度评分；提取实际命中的正文片段作为证据。不得依赖已删除的 query 参数。
3. 向量路用 include_text 生成查询向量，在同一 profile、状态及字段范围中检索，并对整条记忆应用相同 include AND / exclude；两路各自先取有限候选。建议先试每路 20 条不同记忆，这个数是评测起点，不是验证结论。
4. 按 memory_uuid 合并去重，保留两路命中来源；从各 include 的实际命中位置提取原文短上下文，命中标题、关键词等字段时保留对应字段内容。保留字段名与章节路径，合并重叠片段，为每条记忆组装一份精简证据文本。证据按模型 token 预算组织，不设固定块数上限；优先缩短外围上下文，保留各条件的命中依据，不能只取正文前 120 字。仍无法容纳完整命中依据时，按已定 rerank 降级规则处理，不提交缺少部分条件依据的证据文本。
5. 合并后的候选统一进入一个 rerank 阶段：query = include_text，documents 中每条记忆对应一个元素，内容为标题、来源字段/章节路径及汇集的命中原文。证据保留原始自然文本与 Markdown，不用分词串替代；不按召回来源分开重排，也不直接混加两路原始分数。每条记忆得到一个重排分数，据此排序过滤，最终才应用用户 limit；数据库负责完整的 AND 过滤，reranker 依据汇集的证据判断相关性。
6. 只有一个候选也执行相关性判定；评测阈值不沿用未标定的 0.1 或 0.65。相关性不足允许空结果，不补齐数量。
7. 外部仍只输出现有标题、摘要和 ID，随后按原流程 read_memory 全文。
8. 向量路失败时保留可用字面路。rerank 失败、空响应或结果不完整时，只保留字面路已召回且满足全部硬条件的候选；不返回仅由向量路召回、未经相关性判断的结果。区分检索成功但无相关结果与 provider 失败；精确名称匹配的保留规则需用样本固定。

### 索引一致性与恢复边界

- 索引版本覆盖模型、维度、输入拼接与分块策略，并关联源文本 revision/hash；相同模型与维度也能识别策略过时或源内容变化。
- 为每个 profile 持久化一个权威的当前目标 index_version；任务携带启动时的目标版本，不能只信任各 worker 自己的本地配置。
- 单条记忆的全部新块在事务中替换；写入前锁定 profile 目标版本记录及记忆，持锁至提交，与版本切换互斥；同时校验源 revision/hash 未变、任务 index_version 仍等于 profile 当前目标版本。任一不匹配就拒绝写入，保留现有索引，不允许过期任务覆盖新索引。
- 过期任务不得标记成功。回填扫描把源 revision 或 index_version 不匹配的记忆继续识别为待处理，并按当前目标版本重新生成；已有当前有效索引则无需重复生成，首版不另建重试队列。
- 搜索只消费符合当前状态和版本的完整索引。
- 建立/重建任务可暂停、续跑并受 RPM/TPM 预算控制；批准记忆内容与派生索引生成仍异步解耦。
- 恢复、建表迁移和历史向量重建作为单独阶段，执行前核验真实远端状态；本轮不运行服务或回填。

### 验收和迭代顺序

- 先固定一小组人工标注样本：Trending 单项目细节、skill/prompt 末尾条款、短节点、准确名称、用途描述、无关查询及跨块 AND/排除条件。
- 补充证据组装样本：include 分散在标题/关键词与正文、不同章节或多个 chunk；验证各条件依据完整、字段名和章节路径保留、重叠片段合并、外围上下文缩短及预算不足时的降级。
- 补充分块边界样本：超长章节的续块、过长标题路径、代码围栏及正文末尾；验证续块上下文、token 预算和全文覆盖，避免标题重复挤占正文或超限后截去尾部。
- 验收优先级：严格过滤不越界、无关结果尽量少、目标细节可召回、同一记忆不重复；同时记录检索耗时和每次模型请求量。
- 使用离线样本比较旧流程与新流程，选择分块预算、候选数和相关性阈值；不以单次演示宣称整体质量提升。
- 已确认阶段：固定契约与评测基线 → 建立按块派生索引及版本校验 → 高级搜索并行召回与去重 → 记忆证据重排 → 离线调参与验收 → 单独处理恢复/重建。
- 上述阶段不是单轮编码任务；进入开发前继续拆成每轮单一验收目标、单小函数且逻辑 diff 少于 35 行的切片。
