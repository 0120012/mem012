## 1. 流程字符画

### 生成向量流程字符画

以下为主线目标流程，专项已有最小生成、回填及源版本保护，但正常链路尚未接入，完整流程未验收。每个 chunk 独立生成并保存一个向量，全部块在一个事务中统一替换；不再将多个块向量合成一个总向量。维度迁移的具体命令与双槽位流程见[专项计划](EMBEDDING_DIMENSION_UPGRADE_PLAN.md)。

```text
             批准后异步生成 / 受控建立或重建索引
                              |
                              v
                    读取当前记忆与完整正文
                记录 memory_uuid、source_revision
               固定任务模型、维度、输入与分块策略
                              |
                              v
               按内容边界 + 实际 token 预算分块
             短记忆一块，长文多块，覆盖全部正文
                              |
                              v
               每块输入：记忆标题 + 章节路径 + 正文块
                              |
                              v
              排队并按 RPM/TPM 预算请求 embedding
                              |
                +-------------+-------------+
                |             |             |
                v             v             v
             chunk 1       chunk 2       chunk N
                |             |             |
                v             v             v
              向量 1        向量 2        向量 N
                |             |             |
                +-------------+-------------+
                              |
                              v
                  确认全部块完成、向量维度正确
                              |
             失败或超预算 -----+----> 明确失败或待处理
                              |      不发布部分块索引
                              v
               写入事务锁定源记忆，核对 active 与源版本
              保证任务目标与实际读写目标一致（正常链路待落实）
                              |
          源或任务目标已变化 -+----> 拒绝旧结果，不动现有索引
                              |      正常链路由后续扫描补齐
                              |
                              v
                一个事务内替换该记忆的全部块索引
                 每块独立保存向量及块信息、版本
                   全部块关联同一个 memory_uuid
                              |
                              v
                搜索只使用状态与版本有效的块索引
```

## 2. 先看这一页

**目标：找回长记忆中的具体细节，减少无关结果。** 对外仍返回记忆标题、摘要和 ID，再按需用 `read_memory` 读取全文。

**当前进度：P0 已交付；P1 部分实施、尚未验收；P2–P5 待实施。当前在维度迁移专项中补齐 P1 的块生成与回填能力，尚未接入正式读写链路，未完成 HNSW 建索引或切换。**

### 三类工作分别是什么

- **[项目代码]**：修改 `src/` 下的 Rust 程序，以及程序使用的 SQL 和表结构。这些改动才会改变实际服务行为。
- **[Python脚本]**：修改 `scripts/` 下的实验、样本或评测工具。脚本用于准备材料、调用模型、运行实验和采集结果。
- **[测试验收]**：运行检查或基准测试，判断实现是否满足预期。Python 是执行工具之一；写好脚本之后，还要实际运行并留下结果。

另用 **[文档]** 标记契约和报告，用 **[环境操作]** 标记目标环境的迁移、恢复与重建。**P1–P4 只在隔离环境实施和验证；目标环境操作留到 P5。**

文中 embedding 指把文本转换为向量，rerank 指相关性重排；chunk 是正文块，token 是模型计数单位，tokenizer 是分词器。

这里的“基准测试”同时关注检索质量、耗时和模型调用成本。“离线评测”指使用固定标注样本，运行时仍可能连接隔离数据库、调用真实模型。

### 阶段总览

| 阶段 / 状态 | 项目代码要做什么 | Python 要做什么 | 怎么判断完成 |
| --- | --- | --- | --- |
| P0：已交付 | 未修改 Rust | 校验样本、探测模型限制、跑旧流程参考基线 | 有契约、样本、基线和质量线 |
| P1：部分实施、未验收 | 专项已有块表、限速、最小生成回填及源版本保护；结构分块、接线和全库校验等未完成 | 按需辅助检查样本 | 正文完整覆盖，旧任务不能覆盖新索引 |
| P2：待实施 | 两路并行召回、严格过滤和去重 | 复用样本辅助评测 | 候选满足全部硬条件，同一记忆不重复 |
| P3：待实施 | 汇集命中证据，统一重排 | 按需辅助检查证据与评分 | 每条记忆按完整命中依据判断相关性 |
| P4：待实施 | 将评测选定的参数落实到程序 | 补齐真实 Rust 入口的评测与结果采集 | 新流程通过 P0 固定的质量线 |
| P5：待实施 | 按环境核验结果确定必要改动 | 按需准备迁移或重建工具 | 目标环境切换、重建及回滚验收通过 |

执行顺序：**P0 → P1 → P2 → P3 → P4 → P5**。这些是阶段编号，与 `questions.md` 的 P0/P1 问题优先级不同。

专项中的块表、分块、生成、限速、回填及一致性保护归属 P1；其换表、查询验证和恢复能力可在隔离环境预先开发验证，目标环境执行仍归属 P5，须等待 P4 通过并另行确认环境范围。此前已授权在测试 profile `claude` 创建下一代表，不表示已完成正式迁移或可跳过阶段验收。

### 下一步具体做什么

继续 **P1 的块生成与回填**：标题路径已接入生成请求及完整输入预算，按标题边界分块，长章节续块保留路径；下一切片将路径随生成结果写入目标块记录，后续补段落结构分块、全库补扫及切换前一致性校验。专项跑通后仍须补齐日常批准后的异步刷新、同维度内容/策略更新和正常读写链路，不能据此直接勾选 P1 完成。

每次代码开发仍只做一个最小可验证切片：一个验收目标、一个职责单一的小函数、逻辑 diff 少于 35 行。阶段清单不是一次性编码范围；完成一个切片后报告证据和剩余工作，等待明确继续。

## 5. 技术约定：实现时遵守的细节

以下为已确认的目标行为，尚未实现部分按 P1–P5 推进。精确参数、状态、降级与统计规则以[P0 契约](EMBEDDING_P0_CONTRACT.md)为准；此处不新增公开参数或放宽过滤条件。

### 搜索输入与过滤契约

**公开参数：**

- 只保留高级搜索 `terms.include`、`terms.exclude`、`filters` 和现有 `limit`。
- 删除普通 `query` 参数及 query-only 路径，不保留兼容入口，不新增独立检索描述参数。内部旧分支是待移除项。
- terms 与 filters 同时提供；include 和 exclude 两个数组都提供，至少一组非空。具体类型和非法输入规则见 P0 契约。

**内部检索意图：**

- include 去除首尾空白后，以空格拼接为内部 `include_text`。它是唯一检索意图，不是新公开参数。
- include_text 同时用于查询向量和 rerank query；字面路也根据 include 评分、定位命中并提取证据。
- 不为 include_text 另设应用层长度上限或专门超限规则。仅有 exclude 时保持纯过滤，不调用 embedding/rerank。

**两路共同的硬条件：**

- 每个 include 必须出现（AND），每个 exclude 必须不出现；profile、状态、filters 边界一致。
- 硬条件作用于整条记忆的选定字段，允许词分散在不同字段或正文块；filters 限定硬条件的匹配字段。
- 状态与身份规则按 P0 契约：当前 profile 的 active/pending 可见，trashed 不可见；不能跨记忆或 profile 合并。
- 例：include = ["网页", "Markdown"]、exclude = ["付费"]。选定字段必须同时包含“网页”和“Markdown”，不能包含“付费”，用“网页 Markdown”做语义排序。

并行向量路改善严格条件内的候选选择和排序；它不会召回缺少 include 原词的记忆，不因此放宽 AND 或恢复普通搜索。

### 内部按块，外部按记忆

**正文与存储：**

- 保留 `memory_units` 及 `read_memory` 全文接口；分块文本和向量只是可重建的派生索引。
- 每块保存所属 memory_uuid、块序号、正文范围、标题路径与向量；输入携带记忆标题、章节上下文和块正文。
- 每块独立保存向量，不再平均合成一个总向量；完整正文保持原样。
- 元数据（如 keywords、recall_when）是否进入每块输入，由样本检验，避免无关标签污染正文块。

**分块方式：**

- 短记忆一块。长文优先按 Markdown 标题、项目条目、段落及代码围栏划分，超长章节再按 token 预算拆分，必要时少量重叠。
- Trending 各项目优先独立成块；skill/prompt 保留章节路径，避免把无关项目或章节混在一个向量中。
- 每个续块都携带精简标题路径，前缀也计入预算；避免只有首块有标题，或重复标题挤占正文预算。

**输入预算：**

- 使用实际模型的 tokenizer，不能把字符数当 token 数；初始块大小、重叠量和证据预算由样本选择。
- embedding 预算包含标题、上下文、正文与特殊 token；rerank 预算另计 include_text、来源字段/章节路径和证据正文。
- 成本通过排队及任务预算控制；超限明确失败或待处理，不静默丢弃正文尾部。

### 并行召回、去重与相关性判定

**第一步：同时召回两路候选。**

- 同一请求并行执行 pg_trgm 字面路与块向量路，复用 PostgreSQL/pgvector。
- 字面路先严格过滤，再按 include 命中字段、次数、位置及 pg_trgm 相似度评分，提取真实命中位置；不得依赖已删除的 query。
- 向量路以 include_text 生成查询向量，在相同 profile、状态及硬条件内检索有效块索引。
- 两路各取有限候选，按不同记忆计数。每路 20 条只是实验起点，不是固定结论。

**第二步：按记忆去重并汇集证据。**

- 按 memory_uuid 合并候选，保留召回来源，不直接比较或相加两路原始分数。
- 从各 include 的真实命中位置提取原文短上下文；命中标题、关键词等字段时保留相应字段内容。
- 保留字段名与章节路径，合并重叠片段，为每条记忆组装一份证据文本。
- 不只取正文前 120 字，不设置固定块数上限；按 token 预算优先缩短外围上下文，保留各条件的命中依据。
- 完整依据仍放不下时按既定规则降级，不把缺失部分条件依据的文本交给 rerank。

**第三步：统一重排，再过滤和限制数量。**

- query = include_text，documents 中每个元素对应一条记忆的证据，包含标题、来源字段/章节路径和命中原文。
- 保留自然正文与 Markdown，不用分词串替代；不按召回来源分别重排。
- 数据库保证完整 AND 条件，reranker 根据证据判断相关性。每条记忆一个分数，单个候选也要判定。
- 相关性不足可以少返回或返回空；不沿用未标定的 0.1 或 0.65 阈值，排序过滤后才应用用户 limit。
- 对外仍返回现有标题、摘要和 ID，随后按需 read_memory；不要求新增命中片段展示。

**故障怎么处理：**

- 向量路失败，保留可用字面路。
- rerank 失败、空响应或结果不完整，仅保留字面路已召回且满足全部硬条件的候选。
- 不返回只由向量路召回且未经相关性判断的候选；不为凑数补结果。
- 故障与正常零相关结果必须区分。精确名称保留和响应状态遵守 P0 已冻结规则，行为待 P2–P3 验证。

### 索引一致性与恢复边界

**版本由谁决定：**

- 源版本使用 source_revision；模型、维度、输入拼接和分块策略须与索引及查询一致。即使模型和维度相同，也要识别源内容或策略已经过时的索引。
- 当前迁移专项沿用配置中的目标模型和命令指定的维度，不新增 source_hash、index_version、profile 当前代/目标代或迁移阶段记录表。
- 迁移整轮互斥且每轮重建非活动槽位，旧块不跨任务复用；这只约束迁移命令，不能替代日常刷新及同维度策略变化的一致性机制，后者仍是 P1 未完成项。

**什么时候允许写入：**

- 单条记忆全部新块在同一个事务中替换。
- 专项已在写入前锁定源记忆并核验 active 状态与 source_revision，持锁至事务提交；网络请求不持有源行锁。
- 块集合必须连续完整覆盖原文、UTF-8 边界正确且向量维度匹配；模型、维度和读写物理表须匹配，切换前全库一致性校验仍待实现。
- 正常刷新还须防止处理策略或服务目标变化后的旧任务写入；机制与验收未完成。任一不匹配就拒写，保留现有服务索引，不发布部分块或误标成功。

**失败之后怎么补齐：**

- 正常回填须扫描缺失、源版本不匹配或策略过期的索引，按当前策略重新生成；已有有效索引不重复生成。该能力未由专项的最小游标循环覆盖。
- 首版不另建重试队列。搜索只消费符合当前状态、当前版本的完整索引。
- 迁移命令必填 dimension、RPM、TPM，无默认值；请求额度不足等待，每次实际尝试均计数。失败条目继续、整轮失败退出，下次执行清理并重建非活动槽位后全量生成，不复用旧块、不做断点续跑或独立统计模块。
- 只在维度变化时换表，同维度不走换表流程；首版目标维度限制 1～2000，继续使用 HNSW。目标模型来自 config.toml，不新增 --model；当前迁移 tokenizer 仅支持 BAAI/bge-m3，首轮目标 1024 维。
- 批准内容与派生索引生成继续异步解耦，接线及任务预算仍待完成；P1–P4 仅在隔离环境开发验证，P5 才执行另行确认的目标环境迁移、恢复与历史重建。

### 评测样本和参数选择

- 固定样本覆盖 Trending 单项目细节、skill/prompt 末尾条款、短节点、准确名称、用途描述、无关查询及跨块 AND/排除条件。
- 证据样本覆盖 include 分散在标题/关键词与正文、不同章节或多个 chunk；检查各条件依据、字段名/章节路径、重叠合并和预算不足降级。
