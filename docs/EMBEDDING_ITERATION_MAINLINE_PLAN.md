## 1. 流程字符画

### 生成向量流程字符画

以下为主线目标流程，迁移代码已有最小生成、回填及源版本保护，但正常链路尚未接入，完整流程未验收。每个 chunk 独立生成并保存一个向量，全部块在一个事务中统一替换；不再将多个块向量合成一个总向量。维度迁移约束见本文“维度迁移的既有约束与剩余工作”。

```text
             批准后异步生成 / 受控建立或重建索引
                              |
                              v
                    读取当前记忆与完整正文
                记录 memory_uuid、source_revision
               固定任务模型、维度、输入与分块策略
                              |
                              v
               按内容边界 + 实际 token 预算分块
             短记忆一块，长文多块，覆盖全部正文
                              |
                              v
               每块输入：记忆标题 + 章节路径 + 正文块
                              |
                              v
              排队并按 RPM/TPM 预算请求 embedding
                              |
                +-------------+-------------+
                |             |             |
                v             v             v
             chunk 1       chunk 2       chunk N
                |             |             |
                v             v             v
              向量 1        向量 2        向量 N
                |             |             |
                +-------------+-------------+
                              |
                              v
                  确认全部块完成、向量维度正确
                              |
             失败或超预算 -----+----> 明确失败或待处理
                              |      不发布部分块索引
                              v
               写入事务锁定源记忆，核对 active 与源版本
              保证任务目标与实际读写目标一致（正常链路待落实）
                              |
          源或任务目标已变化 -+----> 拒绝旧结果，不动现有索引
                              |      正常链路由后续扫描补齐
                              |
                              v
                一个事务内替换该记忆的全部块索引
                 每块独立保存向量及块信息、版本
                   全部块关联同一个 memory_uuid
                              |
                              v
                搜索只使用状态与版本有效的块索引
```

## 5. 技术约定

本节是实现边界，任务进度只记在第 3 节，历史证据只记在第 6 节。精确契约以 [P0 契约](EMBEDDING_P0_CONTRACT.md) 为准，V3 不新增公开参数、不放宽严格过滤。

### 搜索输入与结果

- 只保留 `terms.include`、`terms.exclude`、`filters` 和现有 `limit`。terms/filters 同时提供，include/exclude 两个数组都提供，至少一组非空；移除普通 query，不新增独立检索描述参数。
- include 去首尾空白后以空格拼接为内部 include_text，同时用于查询向量与 rerank query；不为其另设应用层长度上限或专门超限规则。exclude-only 不请求模型。
- 每个 include 必须出现（AND），每个 exclude 必须不出现。硬条件作用于整条记忆的选定字段，可分散在不同字段或块；不能跨记忆或 profile 拼条件，向量路不放宽原词匹配。
- 两路统一 profile、filters 与状态边界；当前 profile 的 active/pending 可见，trashed 不可见，具体状态行为遵守 P0。索引生成中的 active 校验不能替代搜索状态规则。
- 候选按不同记忆计数、按 memory_uuid 去重，保留来源但不混加原始分数；最终相关性过滤排序后才应用 limit。精确名称保留遵守 P0，不为凑数返回弱相关项。
- 向量路失败保留可用字面路；rerank 失败、空或不完整响应仅保留满足硬条件的字面候选。区分正常空结果与故障，不返回仅由向量路召回且未经判定的候选。
- 外部继续返回标题、摘要和 ID，完整正文由 read_memory 提供；不新增命中片段展示要求。

### 分块与模型预算

- `memory_units` 是完整正文来源；块及向量为可重建的派生索引，保留原文和 UTF-8 字节范围。每块保存 memory_uuid、序号、路径和独立向量，不合成总向量。
- 短记忆一块；长文优先按 Markdown 标题、项目条目、段落及代码围栏划分，超长结构按 token 预算拆分，必要时少量重叠。Trending 项目优先独立，skill/prompt 保留章节上下文。
- 每个续块都带精简路径，前缀计入预算，不能只有首块有上下文，也不能让重复路径挤掉正文。标题前正文使用空路径。
- 预算使用实际模型 tokenizer，包含标题、路径、正文与特殊 token；rerank 另计 include_text、来源字段/路径与证据。元数据是否进入每块输入由样本检验。
- P0 对 embedding/rerank 均按 8192 tokens 组织完整输入。embedding 的 8193-token 请求返回 400；rerank 超窗返回 200 的内部处理方式未证实，不依赖服务保证证据完整。
- 证据保留自然正文/Markdown，按各条件真实命中位置提取并合并上下文，不只取开头或固定两个块。完整依据仍放不下时按 P0 降级，不送缺条件依据的文本重排。
- 块预算、重叠量、元数据、候选数与阈值由 tune 集选择；通过排队和任务预算控制成本，超限明确失败或待处理，不静默丢尾部。固定 tokenizer 的 revision/hash 见[模型限制记录](embedding_p0_model_limits.json)及模型目录 README。

### 索引一致性

- 源版本使用 source_revision；模型、维度、输入拼接和分块策略必须与索引、当前任务及查询一致。模型/维度相同仍可能策略过期。
- 每条记忆的完整新块集合在同一事务替换。网络请求不持源行锁，发布时锁定并核验源状态/版本和目标策略；失败不得发布半套或误标成功。
- 正常回填识别缺失、源过期或策略过期索引，有效索引不重复生成；首版不另建重试队列。搜索只消费符合当前版本的完整索引。
- 当前迁移实现只保护 active/source_revision 和本轮迁移目标；整轮互斥不能代替正常刷新、同维度策略变化及旧任务晚完成保护。正常块存储已由 P1.2 的源锁、目标代号与事务替换保护，迁移命令适配仍留在 P5。

P1.2 目标保护采用按 memory_uuid 定位的 memory_embedding_targets：目标独立于已发布块，避免新策略生成失败时丢失旧索引或放行旧任务。生成前登记源版本、模型、维度及输入/分块策略，并取得递增 generation；发布在源行与目标行锁内比对这些字段。最新登记的生成请求定义当前目标，A→B→A 也不能复用旧代号。当前策略标记为 metadata-v1:heading-path-v1:full-input-8192:tokenizer-21106b6d7dab2952c1d496fb21d5dc9db75c28ed361a05f5020bbba27810dd08，固定输入拼接、标题分块、完整 token 预算与 tokenizer；语义变化时必须更新。生成失败不删除目标、不清空已发布块。已接目标表生命周期、登记、生成、源比较、发布核验及事务替换；正常块写入同时保存 embedding_policy/target_generation，表示实际发布快照，不随新目标登记变化。迁移旧路径仍写双 NULL，仅表示未知策略，后续阶段不得将其判为策略有效。

### 维度迁移的既有约束与剩余工作

以下约束保留为 P5 依据，不是当前任务入口。P1.1–P1.3 已完成，下一项为 P1.4；不得从本节启动迁移或恢复支线。

- 沿用 `prepare-embedding-next`，目标模型取 `config.toml` 的 `[embeddings].embeddings_model`，不新增 `--model`。`--dimension`、`--rpm`、`--tpm` 必填且无默认值；维度限 `1..=2000`，继续 HNSW，不新增高维分支。
- 当前迁移 tokenizer 仅支持 BAAI/bge-m3，其他模型在重建前拒绝；首轮目标为 1024 维。模型必须真实支持输出维度，不对旧向量补零或截断。
- 只在维度变化时换表，同维度拒绝准备。固定复用当前服务与非活动下一代表两个槽位；确认非活动后在当前表同 schema 内清理重建，不用 CASCADE；依赖阻止删除时事务回滚，当前服务与旧数据保留。
- 每轮全量重建，不复用旧块、不做断点续跑，不新增 source_hash、index_version、profile 当前代/目标代或迁移阶段记录表。历史空表复用和默认维度/限速已取消。
- 单 profile 整轮互斥、串行请求、小批读取、逐记忆处理；逐条输出成功/失败 JSON，单条失败继续、整轮失败退出。不自动后台化，不新增用量报表或独立统计模块。
- 最近 60 秒窗口计完整输入及特殊 token；每次实际尝试与重试计数，额度不足等待，单次超 TPM 拒绝；沿用 5/20/60 秒退避，永久错误直接失败。
- 2000 RPM、500000 TPM 是用户提供、P0 保守视为共享的上限，未独立撞限验证；独立 CLI 进程计数不保证账户级协调。P0 的最多 64 次请求、至少 1 秒起始间隔仅属于那次评测，不是本轮预算。
- 双代并存需要额外磁盘空间。切换前补扫游标之前发生的修改、缺失和不完整块，在一致锁边界内复核模型/维度、源版本及全库覆盖；检查失败旧代继续服务。
- 查询模型、维度、阈值与物理表须匹配。校验后建 HNSW cosine 索引并协调切换；查询验证失败须恢复旧代路由，通过后保留上一代，下次确认其非活动后才回收。
- 剩余开发与目标环境动作统一列在 P5，只有在主线验收确实需要时才提前于隔离环境开发；不作为 P1 正常链路的前置条件。

已有命令形式为 `mem012 --profile claude prepare-embedding-next --dimension 1024 --rpm 50 --tpm 500000`。它仅说明语法，数值不是默认值、安全额度承诺或执行授权。
